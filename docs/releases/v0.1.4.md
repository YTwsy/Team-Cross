# Team Cross v0.1.4

`v0.1.4` 是面向 Apple Silicon、macOS 14 及以上的预发布版本。会话、模型调用与代码执行仍保留在发起者的 Mac；本次重点补齐 Claude Code 协作 fork 在发起者个人 CLI/TUI 历史中的连续性，并修复较新 Codex CLI 下的动态 MCP 运行时兼容问题。

## 安装

- **App**：下载 [DMG](https://github.com/YTwsy/Team-Cross/releases/download/v0.1.4/Team-Cross-0.1.4-arm64.dmg)，将 `Team Cross.app` 拖入“应用程序”并打开。
- **独立 CLI**：下载 [arm64 CLI](https://github.com/YTwsy/Team-Cross/releases/download/v0.1.4/teamcross-0.1.4-darwin-arm64.tar.gz)，解压后将 `teamcross` 放入自己的 `PATH` 目录。

本预发布包使用 ad-hoc 签名，未使用 Developer ID 签名或 Apple 公证。首次打开若受到系统提示，请先尝试打开 App，再到“系统设置 → 隐私与安全性”中确认。

Homebrew tap 是 Release 之后的独立发布步骤，本次预发布不更新公共 Formula 或 Cask；`YTwsy/teamcross` 仍指向此前已发布的版本。

## 主要变化

- Claude 协作改用原生 `--fork-session` 创建新会话；发生首次业务输入并由 Claude 持久化后，这个 fork 会出现在发起者个人 Claude Code CLI/TUI 的 `/resume` 历史中，结束共享后可以从个人历史继续。
- 每个 Claude 协作使用独立 runtime，只复制用户选中的来源 transcript，并只向个人历史发布新 fork 的单文件入口；Team Cross 不改写个人设置、插件、已有历史、来源 transcript 或认证原件，也不把其他个人历史暴露给协作 worker。
- Claude 恢复和结束流程按协作所有权连接、停止精确的原生 job；不同协作的后台任务彼此隔离。零输入 fork 仍允许尚未落盘，也不以个人历史可见作为创建成功门槛。
- Codex 的 MCP 枚举与 app-server 启动现在复用同一组运行时隔离参数，避免较新 Codex CLI 中插件动态提供的 MCP transport 在共享运行时被错误继承并导致恢复失败。

## 当前范围

项目仍处于原型阶段。当前只提供 arm64 产物；Intel、自动更新和登录自启尚未提供。Claude Code 接入仍为实验性：本轮验证 Claude Code `2.1.270` 的个人 CLI/TUI `/resume`，不覆盖 Claude Desktop、Web 或 Cloud 历史。项目处于 prerelease，旧独立 `claude-home` 协作不迁移；跨磁盘单文件 symlink fallback、OAuth / Keychain 登录以及共享期间从个人 `/resume` 并行打开同一 session 尚未做真实验收。

本轮完成 Go test/vet、相关 race test、Web 类型检查与 49 项交互测试、production Web 构建，以及同机两个 Core 的真实 Luna Claude 和 Codex 运行时回归。两台 Mac 的真实 LAN、防火墙与睡眠恢复、完整原生窗口和首次系统批准流程没有重新验证，不能由同机测试替代。具体边界见 [Claude 个人 CLI/TUI 历史验收](../agent-wiki/sources/validation/claude-personal-history-2026-09-14.md) 与 [Codex 动态 MCP 和运行时恢复验收](../agent-wiki/sources/validation/codex-runtime-mcp-2026-09-14.md)。
