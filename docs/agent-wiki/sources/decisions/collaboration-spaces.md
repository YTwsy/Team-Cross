# 只读分享与多人协作空间

状态：本地原型已实现空间、材料、多人及可选执行的主要闭环。本文保存产品范围与设计契约；实际环境与未覆盖项目分别记录，不能推导为三台 Mac 实网已验收。

## 已确认范围与设计基线

用户已明确确认：

1. 允许独立分享 Session 供阅读和讨论，不要求创建可执行的原生 fork。
2. 第一版就支持三人及以上同时参与，不能以只完成 A/B 双人的结果作为这一版的完成标准。

此前讨论的目标包括：任一参与者都能发布自己选择公开的多个 Session；材料可附到空间或具体讨论；人通过 WebGUI 浏览，个人 Agent 和共享 Agent 按需读取；公开范围与建议阅读起点分别处理。

以下为据此收敛的实现基线。它们说明本次方案的取舍，不将每一项都标记为用户逐项确认：空间由一台主机托管；材料以固定范围和版本发布到该主机；首版每个空间最多关联一个可操作的原生协作会话；更新主动发布；加入资格、讨论权限与当前输入归属分别管理。

名词和对象身份由 [核心词汇](../product-core-and-glossary.md#协作空间的对象边界) 统一维护。`Record` 保存空间及材料，`execution` 是可空的独立对象；可复用邀请链接和独立成员身份共用空间的传输。只读空间没有虚构的原生会话 ID，也不共用 `remote` 输入身份。

用户确认的组织方式如下。可操作的协作会话为可选项；独立只读空间可以没有这一项，其他部分保持相同结构。

```text
协作空间
├─ 参与者与邀请
├─ 多份已发布会话材料
│  ├─ A 的分析，版本 1
│  ├─ A 的验证，版本 1
│  └─ B 的审阅，版本 2
├─ 批注与回复
└─ 一个可操作的协作会话（可选）
   └─ 原生 fork、执行目录、权限和当前输入者
```

材料版本属于具体发布材料，不是空间或原生 fork 的版本。参与者、材料和讨论属于空间；原生 fork、执行目录、运行权限和输入归属属于可操作会话。

## 三种使用形态

| 形态 | 用户动作 | 应得到的行为 |
| --- | --- | --- |
| 分享与审阅 | 选择个人 Session 和公开范围，创建空间并邀请 | 只有已发布材料和讨论；不创建原生 fork，不创建 worktree，不启动业务轮次 |
| 共同继续 | 明确创建一个可操作的协作会话 | 使用新的原生 fork，明确执行主机、目录、受限/信任模式和输入归属 |
| 独立分析后交流 | 各自的个人 Agent 按需读取，再发布自己的分析 | 本地个人上下文保持独立；发布不会合并完整历史或自动启动其他 Agent |

这三种形态可以出现在同一空间。用户从一个具体 Session 发起即可，不要求先建立 Project、填写问题描述、摘要、调查类别或成果验收。空间可以只有一份材料，也可以包含多份材料；不要求指定一个负责最终综合的主 Agent。

只读分享不要求来源目录仍是可执行的 Git 工作区；可读取的原生历史是其前提。读取历史可以使用 Provider 所需的只读控制进程，但不能因此恢复来源为可写或发送业务输入。可执行协作继续满足现有 Git、原生 fork 和目录约束。

## 主机与执行边界

- 空间发起者的 Core 托管空间、成员、材料和讨论。参与者通过各自的 Core 发布自己本机明确选择的内容；托管主机不因此取得参与者其他会话或目录的读取权。
- 第一版若启用共同执行，执行也留在空间托管主机。来源必须由该主机实际访问并核对；B 发布一份历史，不代表 A 已经取得 B 的原生可恢复会话、代码或工具环境。
- 每个空间最多关联一个可操作的协作会话；它具有独立的运行状态和输入归属。个人 Agent 可以同时分析，增加只读材料不增加共享执行进程。
- 从只读讨论启用共同执行，是明确的新动作。创建预览说明将额外共享的原生历史、目录读取和执行权限；原来的片段发布授权不能隐式扩大为完整 fork 或文件访问。受限/信任模式只适用于执行，不给纯只读空间填造一种运行模式。
- 发布片段不是可原生恢复的 fork。跨 Provider 读取材料属于参考分析；不承诺跨 Provider 无损续接或复制运行环境。需要在另一位参与者主机上共同执行时，由该主机所有者另建可执行协作；首版不迁移空间主机或运行中的执行。

新建和恢复原生协作仍遵守 [目录与生命周期](workspace-and-lifecycle.md) 与 [协作模式](runtime-modes.md)。只读发布需要独立操作语义，不能悄悄把现有 `share_current_session` 从创建 fork 改成另一种效果。

## 多人成员与输入归属

第一版至少覆盖一位发起者 A 和两位受邀者 B、C 同时加入；三人是最低验收规模，不是固定人数上限，也不构成无限人数承诺。

| 能力 | 发起者 | 已加入成员 |
| --- | --- | --- |
| 读取已发布材料、批注和回复 | 可以 | 可以 |
| 发布自己选择公开的材料 | 可以 | 可以，不要求执行输入权 |
| 更新或撤回自己发布的材料 | 可以 | 可以，不可冒充其他发布者 |
| 复制、关闭或重置链接及移除成员 | 可以 | 首版不提供转邀权限 |
| 创建空间内的共享执行、选择目录和模式 | 在托管主机明确操作 | 可提出请求，不能隐式启用主机执行 |
| 申请或取消输入 | 发起者管理交接 | 可以；申请不会自动取得输入 |
| 发起者向具体成员交出输入、接回输入 | 可以 | 首版不提供成员之间直接转交 |
| 交还输入 | 不适用；需要时使用接回 | 当前输入者可以交还给发起者 |
| 输入、补充、中断、审批、执行模型设置 | 仅当前输入者，且遵守 Provider 能力 | 相同约束 |

成员使用各自的稳定身份和独立凭据。作者、输入申请、在线状态、直接连接和去重键都绑定具体成员，不能继续以共同的 `remote` 值区分多人。写入去重至少区分成员、动作和请求标识，内容变化不能被当成同一成功请求。

同一空间在一次共享期间维护一份当前邀请链接，允许多人分别加入，有效至关闭、重置或本次共享结束。每位成员使用独立凭据，重复加入请求复用同一身份。关闭或重置链接只影响后续加入，已有成员继续参与。链接明确空间、主机和加入时的访问范围；成员凭据不能用于其他空间。持有效链接即可加入，不核验预先指定的账号；移除只撤销现有凭据，阻止再次以新身份加入需关闭或重置链接。

成员发布即面向该空间获准成员开放。新增成员也能读取空间内尚未撤回的已发布材料，此规则同时出现在发布和邀请说明中。第一版采用空间级读者范围，不增加材料级私密小组。

共享执行同一时刻只有一个输入者、一个直接原生客户端。发起者可以看到多个输入申请，主动选择交给哪一位；排队不自动调度模型或转移输入。交接要求当前 `epoch`，关闭旧直接连接；交出和交还等待当前轮完成，接回不隐式中断。直接客户端、个人 MCP、CLI 均经过同一检查。

离线不自动撤销成员或转移输入。当前输入者主动离开或被移除时，撤销其入口、提升交接版本并将控制归还发起者；已经运行的业务轮次不因此自动重放或被描述为已结束。C 的阅读和讨论继续有效。已被撤销成员的并发旧请求必须拒绝，不能因仍持有本机代理连接而继续写入。

## 发布范围、版本与数据面

选择提供两条主要路径：全部已完成对话，或从具体提问开始到指定完成位置的一段连续对话。一次提问及其可读取的完整执行过程作为选择单位；不要求用户填写原生 ID 或轮次编号。搜索和跨页定位帮助选择，实际发布边界绑定稳定内容身份。

公开范围与建议阅读起点独立。后者只改变导航，不改变访问权限。选择页面固定截至位置；新增对话不能在发布时被悄悄纳入。通过个人 Agent 操作时，来源身份沿用当前会话核对机制；边界不明确时先展示候选范围，不能按最近会话或模型推测扩大公开内容。

发布预览列出实际包含的用户消息、助手可见回复、已保存工具调用和输出，以及实际可提供的附件。折叠不等于排除。无法解析、缺失或截断的内容明确标识，不能宣称完整；不沿会话中的任意文件路径自动收集原目录文件，也不把 Provider 配置、认证或整份原始历史目录作为发布包。

参与者从自己的主机导出选定内容，经现有明确选择的 LAN 或 Tailcat 通道上传到托管主机。材料发布成功后，该主机保留固定内容；发布者离线不使已发布材料失效。托管主机离线则无法继续远端读取，不承诺云端持久服务或跨主机迁移。

每份材料有独立身份和版本，保留发布成员、Provider、公开范围及可核对的来源关系；跨引用保留所读版本，避免把复述同一来源当成多次独立验证。协议字段、文件布局及大小限制在实现时写入 [协议](../protocol.md)，本页不预先宣称路由已经存在。

WebGUI、个人 MCP/CLI 与共享运行时工具只通过该空间内的发布对象读取材料。目录先返回必要元数据；正文按需读取并可继续分页。未公开内容不得通过搜索、摘要、游标、原生会话 ID、文件入口或通用上下文工具泄露。范围外仅说明存在未公开内容，不显示其标题、原文或自动摘要。

发布新版本不改写旧版本及既有引用；后续个人对话不自动同步。范围扩展属于新的公开动作。结果不明时查询发布请求，持久化成功前不能报告已发布，断线不自动重放。

## 讨论与 Agent 参与

材料可直接附到空间，也可关联具体消息、批注或回复。同一份已发布材料可被多处引用，引用保存版本与定位，不将每次引用变成一份新的独立调查。

批注需要能指向已发布材料中的原文或可操作会话中的上下文，两者的身份与读取入口不能混淆。材料撤回、版本更新或原生现场变化后，旧引用说明对应状态，不猜测新的位置。

个人 Agent 与共享 Agent 都可以在权限范围内查看目录、按需读取、引用和回复。共享运行时只取得当前空间中已获准的材料与讨论能力，不因新增读取工具获得个人来源枚举或其他空间的访问权。来源中的过去指令作为参考内容，不自动成为当前任务授权。

收到材料或批注可以产生更新提示，但不自动发起或补充模型轮次。发布者不必取得共享输入权；用户要求模型处理时，才按对应客户端、Provider 和输入归属操作。区分已发布、已读取、已回复和实际执行结果，不把工具读取完成标记为已理解或已验证。

## 退出、撤回与保留

- 撤回材料停止通过空间继续读取，历史引用标记撤回。已经被读取、复制或引用的内容不能保证召回；撤回也不删除原生来源。
- 成员离开或被移除时，其访问资格终止，已正式发布到空间的材料和讨论默认保留；要撤回材料，应执行明确的材料动作。其他成员的资格保持有效。
- 发起者结束共享关闭所有远端访问，保留空间材料、讨论、个人会话和目录。已有共享执行按当前轮、审批及连接状态完成释放；结束共享不自动中断模型或删除 worktree。
- 发起者退出或重启 Core 后不自动复活旧邀请和成员资格；重新开放时明确生成新邀请。参与者单独重启仍可按有效凭据重连，不重复加入。失败或中断的发布、创建请求不自动重放。
- 空间共享状态、成员在线状态、材料可读状态和执行状态分别表达。当前仅因主机不可达时显示断线，不能推断共享已结束或材料已撤回。

## 当前实现进度

已实现独立只读空间、可选 `execution`、固定范围快照、材料版本、逐人发布与撤回、固定版本的原文批注和回复附件。WebGUI、个人 MCP/CLI 和共享运行时读取统一走材料对象。多人邀请与输入交接的前置验证见 [多成员基础](../validation/multi-member-2026-09-18.md)。

启用共同执行保留空间链接、连接和成员身份，既有发布者继续更新自己的材料。原只读链接与成员不会自动获得执行访问；发起者在成员列表明确开放或收回该成员的原生历史、目录和执行访问，输入另行交接。收回执行访问保留材料和讨论资格，关闭其直接连接并接回输入，不自动中断已运行的模型。通过直接执行空间的链接加入时，按邀请已声明的执行范围授权。

只读空间即使未生成邀请或没有成员加入，也始终可“关闭空间”；关闭状态持久化，保留材料和讨论，可重新开放。结束整个共享、成员离开或被移除、主机 Core 退出/重启才结束成员资格。跨共享周期的发布者身份恢复暂未实现。

源快照最多 2048 轮 / 16 MiB 原生响应，一份发布最多 4 MiB，空间全部材料版本累计最多 64 MiB；超限明确拒绝。单条导出文字超过 256 KiB 时保留最多 64000 个字符并显示截断说明。原生文件附件不复制，无法导出的类型显式占位；因此材料不是可恢复的完整原生 Session。首版提供本机会话搜索、公开范围下拉定位、固定版本切换及轮次增改删数量；复杂附件导出、材料全文搜索、跨版本逐字 diff 和来源继承关系图仍未实现。

## 实施顺序与首版完成标准

以下是同一首版内部的实施批次；每一批可独立检查，但只有全部必要能力完成后才能宣称本契约已实现。多人不是后续版本的可选项。

| 批次 | 主要改动 | 阶段验收重点 |
| --- | --- | --- |
| 1. 空间与成员 | 拆分空间和可选执行，建立成员集合、可复用链接与独立访问凭据 | 无 fork 的空间成立；A/B/C 同时加入；撤销 B 不影响 C；跨空间访问被拒绝 |
| 2. 材料发布与读取 | 原生来源核对、范围导出、主机持久化、版本及统一读取限制 | A/B/C 均可发布多份材料；未公开部分在所有读取路径不可达；重复和中断请求不产生重复发布 |
| 3. 讨论与引用 | 空间、消息和材料的引用，批注回复及个人/运行时工具 | 每条回复有具体成员来源；从引用定位到固定版本；读取和回复不启动其他模型 |
| 4. 多人执行接力 | 具体成员输入申请、选择交接、撤销与原生入口隔离 | B/C 同时申请不自动交接；旧 epoch 拒绝；B 离开后 C 仍可读；仅选定输入者能够操作 |
| 5. 完整入口与界面 | WebGUI 范围预览、材料浏览、更新、成员；MCP/CLI 等价路径 | 独立只读分享可直接发起；从讨论明确启用执行；三位参与者完成个人分析回传和接力 |

改动入口以现有 [协作类型](../../../../internal/collab/types.go)、[共享成员](../../../../internal/sharing/sharing.go)、[网络与生命周期](../../../../internal/collab/network.go)、[MCP](../../../../internal/mcp/server.go) 和 [WebGUI](../../../../packages/web/src/components/) 为起点。可重构当前原型，不恢复旧 Thread/Round/Evidence/managed Bridge，也不维持旧数据与旧协议兼容。

完成代码后运行 [工程与网络门槛](../validation/test-gates.md)，更新 Web 嵌入资源并做真实浏览器及截图复核。新增回归至少包括：

1. 纯只读创建、读取、讨论不创建 fork/worktree、不发送模型输入；无可用执行目录仍可分享可读取历史。
2. A/B/C 三个独立 Core 的同链接加入、并行读取/发布/回复、逐人退出与撤销；成员与请求身份不可串用。
3. 公开边界在目录、正文、分页、搜索、引用、附件和原生执行入口上保持一致；不以 UI 隐藏代替数据面隔离。
4. 发布时源继续变化、上传失败、丢失响应、重复请求、Core 重启、材料更新和撤回均具有明确结果。
5. 多人输入申请、交接竞态、旧连接、审批、成员离开及当前执行继续状态；Provider 特有能力分别验证。
6. 当前只读材料授权不会自动授予完整原生历史、文件或执行访问。

同机三 Core 结果必须标为同机验证，不能推广为三台 Mac。三人实机 LAN、跨网络 Tailcat、直连和强制 DERP 分别记录实际环境；原有双人验收不自动覆盖多人。真实模型只用 `gpt-5.6-luna` 和专用测试会话、仓库；只读和状态检查不为取证额外启动模型。完成后精确关闭本次测试进程，保留用户客户端和源目录。

## 重新评估条件

每空间多个可操作运行时、空间主机转移、个人会话自动实时发布、材料级不同读者范围、成员转邀、跨 Provider 原生恢复或文件环境搬运，都需要单独定义权限、生命周期及验证范围；不由“支持多个 Session”自动推导。
