# 空间事件与 ChatGPT Cloud 接收

本页维护持续关注的授权、数据范围与投递语义。协议字段见 [协议](../protocol.md#空间事件网关)，检查要求见 [验证门槛](../validation/test-gates.md#空间事件)，实际结果见 [证据入口](../validation/evidence-map.md#配对与空间请求)。

## 与 LAN 协作的关系

LAN/Tailcat 加入、成员身份、空间请求和成员本机原生接收保持原有路径。事件服务只为支持 MCP Events 的云端宿主提供通知；不创建云端入口仍可完成本机和 LAN 协作。空间 mention、连接当前会话、读取材料都不会自动订阅。

成员在参与会话面板明确创建一份当前空间的连接凭据，随后在 ChatGPT 明确选择关注范围和处理方式。凭据七天到期，只返回一次，Core 只存哈希。创建丢失回执时先检查并撤销可能已创建的连接，不自动生成第二份凭据。面板允许暂停、恢复或撤销连接与单项订阅。授权不赋予项目执行、发布材料、批注回复、修改简报或向其他会话发送请求的能力。

## 事件与处理回执

支持简报更新、公开讨论更新和请求完成/失败结果；讨论可限定原批注，请求可限定请求 ID。事件只携带空间与来源 ID、版本/回复数或状态，不推送私人历史、用户正文或工具执行内容。接收者按需调用受限读取工具核对当前可访问的来源。

订阅建立时记录当前基线，不重放此前内容；暂停保留基线，恢复后可收到暂停期间仍可见的变化。空间状态按三秒间隔观察，连续变化可合并为最新可见版本，不是每次修改的审计日志。事件创建和投递状态持久化；重试沿用事件 ID，宿主需去重。失败传输最多尝试六次并退避；410 撤销订阅，413 和其他不可重试错误停止投递。过期/撤销的待投递事件取消，终态事件保留七天；存储达到上限时暂停订阅，避免静默丢弃待投递事件。

HTTP 2xx 只表示宿主收到；`read_space_event` 单独记读取回执，`finish_space_event` 单独记模型报告的完成/失败与摘要。相同结果可重复确认，不同终态拒绝覆盖。处理回执不等于团队决定或新请求授权，模型建议仍需通过原有人工确认流程纳入简报。

每次订阅、读取和投递都重新核对空间访问；成员离开/被撤销、空间关闭或引用撤回后，不以缓存事件正文兜底。暂停或撤销取消本机正在进行的回调；已经被远端接收的通知不能声称撤回。

## 独立入口

`teamcross events --data-dir <目录> --listen 127.0.0.1:43211` 启动独立、仅监听回环的事件网关。它只接受 `/mcp`，使用 `TC_EVT_…` 空间凭据，再通过单独认证的内部调用访问 Core 的事件接口。不能将远端 token 当作 Core Bearer，不能访问 Core 管理、UI 写入、任意 URL 或原生 RPC。公网 HTTPS 和宿主配置是单独部署事项，不能把整个 Core 反向代理出去。

协议按 [OpenAI MCP Events](https://developers.openai.com/plugins/build/mcp-events) 实现 MCP 2.0 `2026-07-28` 发现、事件目录、订阅、取消和只读工具。回调必须为 HTTPS；验证签名 challenge 后才能保存订阅。每次连接重新验证全部 DNS 地址并固定拨号目标，拒绝私网/保留地址、重定向和环境代理；签名使用 Standard Webhooks，密钥轮换短期双签。

当前已完成本地协议与隔离入口检查。用户明确暂缓真实 ChatGPT Cloud 宿主验收，未部署公网服务；不能据此声称已经从云端唤醒某个 ChatGPT 会话，也不能把本机 `openai/session` 关联键当作云端投递地址。实现入口：[事件管理](../../../../internal/mcpevents/manager.go)、[签名与出站验证](../../../../internal/mcpevents/webhook.go)、[Core](../../../../internal/collab/space_events.go)、[独立 CLI](../../../../cmd/teamcross/events.go)、[订阅界面](../../../../packages/web/src/components/SpaceEvents.tsx)。
