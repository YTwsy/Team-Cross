# 顺流感知

顺流感知在会话下一次正常工具交互或 UserPromptSubmit Hook 中附带相关更新，不唤醒会话，不启动或补充模型轮次。它与主动空间请求、Cloud 事件订阅分别授权；安装插件、打开面板、读取材料、同一 cwd 都不等于开启。

## 第一版分发范围

| 来源 | 接收范围 |
| --- | --- |
| 简报新版本，保留条目状态与作者 | 明确开启该空间顺流感知的会话 |
| 协作会话的新评论与回复 | 归属 executionId 对应的协作会话；回复沿原评论归属，无原文锚点的意见也包含 |
| 主动留言 | 明确选择且已开启顺流感知的空间目标；linked 足够，不要求已接通主动接收 |
| 空间请求完成或失败 | 原请求中记录的同成员、同 Provider、同会话身份；人工发起的请求不猜测回传会话 |

空间讨论和材料评论不自动广播给会话。[成员关注](member-activity.md)只控制人的界面提醒，不自动建立顺流接收关系，人的已读不推进此处投递版本。内容可被空间成员读取，不意味着应该附带给每个会话。个人目标以本机配对和空间目标关联核对；协作会话以原生会话身份与 executionId 核对。不得以最近会话、成员身份或目录推断。

## 开启与留言

参与会话卡片设置自己的目标；协作会话评论区由空间发起者设置。Agent 仅在用户明确要求后使用 `configure_space_inflow` 设置当前已关联会话，不能选择别人的原生会话。首次开启记录当前基线，之后仅附带新变化；关闭保留基线与投递记录，重新开启可继续提供仍可访问的变化。

解除个人目标关联会关闭其顺流感知，重新关联后需要再次明确开启。协作会话的评论开关属于 executionId，移除可选的目标别名不取消该独立开关。同一原生会话有多个空间目标别名时，模型配置工具拒绝猜测目标，由成员在界面选择；投递逐个检查有效关联，不让另一个别名覆盖待投递内容。

协作会话下的评论本身就可作为留言；不需要为了接收评论再关联一次目标。个人会话使用指定 targetId 的空间留言。留言正文 1–300 字，空间内可见，使用唯一 requestId 幂等保存；不承担执行请求的接收、读取和完成状态。发布不自动要求目标回复，也不自动成为团队确认决定。结果不明时查询同一留言 ID。

明确校验失败保留可编辑草稿。连接中断等结果不明时锁定原正文和 ID，只查询状态；查询确认未找到后可由用户明确重试相同 ID 与正文，不自动重发。

## 投递与去重

Hook 与 MCP 共用空间内按接收对象保存的投递版本。每批最多三项、条目 JSON 不超过 4096 字节；简报与讨论连续变化合并为当前可见版本，评论预览提供最新正文或最新回复及来源 ID，不作为完整修改日志。MCP 追加第二个 text content block，包含原工具结果的整个 result 编码预算不超过 65536 字节；不足时原结果不变，该批继续待投递。

准备批次不更新已投递记录。Core 暂存三十秒批次租约避免 Hook/MCP 并发重复；写出失败或预算不足释放租约。输出成功后由传输内部提交该批实际版本，持久化后用于下次去重。模型不调用 ack，不报告已读、理解或完成，也不修改原业务请求。进程在写出与记录之间退出、宿主超时丢弃等极端情况可能导致遗漏或重复；不承诺端到端必达。

每次准备重新核对访问、目标关联和会话身份；关闭空间、撤销成员或关联后不提供新附带内容。绑定运行时只能访问本空间。提醒正文是带来源的外部参考数据，不能覆盖当前指令、输入权或读取权限。已经输出的内容无法召回。

## 接入与边界

- 个人 MCP、插件中的模型工具和绑定运行时 MCP 在成功的工具响应后检查；面板后台读写、mention 搜索和打开面板不消费投递记录。
- `teamcross inflow-hook --provider codex|claude --data-dir <目录>` 从 stdin 只读取 `hook_event_name` 与 `session_id`。只处理 UserPromptSubmit，不读取 prompt、cwd 或 transcript。没有身份、Core 或有效关联时静默退出，不启动 Core，也不增加断线通知链。
- `--print-config` 输出 Hook 配置而不修改用户文件；Codex 本机插件包提供 `hooks/hooks.json`。非托管 Hook 仍由原生宿主审阅和信任，安装插件不等于已信任或会话已开启。
- 受限执行模式继续禁用 Hook，使用绑定 MCP；信任模式遵循当前原生 Hook 配置。没有可用 Hook 或 MCP 交互时不会即时投递。仅有云端本机关联键不等于可以运行本机命令 Hook。
- 不生成或覆盖 `AGENTS.override.md`，不建立后台模型轮询或断线重放链。

配置格式依据 [Codex Hooks](https://learn.chatgpt.com/docs/hooks) 与 [Claude Code Hooks](https://code.claude.com/docs/en/hooks)。实际被测范围见 [证据入口](../validation/evidence-map.md#顺流感知)，协议见 [顺流感知接口](../protocol.md#顺流感知接口)。
