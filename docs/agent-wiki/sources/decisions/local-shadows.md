# 本机数字分身

本页维护分身的共享范围、上下文、记忆、后台任务与恢复契约。首版接入本机 Codex；Claude 后续适配，不提供对话中途更换 Harness。实现入口为 [shadow](../../../../internal/shadow/)、[空间桥](../../../../internal/collab/shadows.go) 和 [聊天界面](../../../../packages/web/src/components/SpaceShadows.tsx)。实际验收范围见 [证据入口](../validation/evidence-map.md#本机数字分身)。

## 空间与运行归属

空间中的成员可以在自己的 Mac 上创建分身，明确指定名称和工作目录。一个分身只属于一个空间；同一分身只有一条持续共享的聊天，整个空间可读、可参与，新成员按现有空间规则阅读历史。消息作者来自经核验的成员凭据，客户端不能指定其他作者。

空间主机保存共享视图，运行分身的成员 Core 保存原文、任务、记忆、交接与原生投递账本。运行留在创建者的 Mac。这与现有共同执行的 fork、输入交接和原生直接客户端分别管理：所有成员可以向分身发送普通消息，Core 串行投入当前主会话；成员不因此取得原生控制或审批权限。

首版通过独立 app-server 使用本机有效 Codex home 和工作目录，不裁剪原生模型路由、认证、权限、MCP、插件、hooks、skills 和记忆加载配置，不改用户配置文件。分身的动态工具是附加能力。原生工具可能访问工作目录以外的资源，分身不构成额外只读沙箱；创建页面说明共享输入范围。模型和推理强度在创建时选择一次；产品不固定套餐或模型。

现有私人会话 P0 不会被 fork 或自动读入。原生配置中明确启用的个人记忆仍按原生规则加载，不能把“未导入 P0”说成完全隔离个人资源。

## 启动模型配置

创建表单根据工作目录读取本机 Codex 的有效 `config/read` 和完整分页 `model/list`，预填当前模型、Provider 和推理强度。用户选择模型和该模型公布的推理选项；Provider 沿用当前原生路由，不另加套餐或账户选择。读取模型列表只启动短期元数据进程，不创建原生 thread、不发送模型输入；结束后关闭进程。未在目录中的已配置自定义模型仍保留，能力未知时要求明确填写推理强度，并由原生创建响应核对，不替换成其他模型。

Core 在创建分身时持久保存不可变的 `settings:{model,modelProvider,reasoningEffort}`。首次 S1、后续 S2/Sn、独立 W、CM、M 的 `thread/start` 和重启的 `thread/resume` 全部显式应用这组值；各 `turn/start` 再传相同 model/effort。暂停/恢复、换段、后台任务更新或重启均不重新读取模型默认值，不提供逐消息选择或运行中修改入口。创建重试沿用同一 requestId 和完整 settings，设置不一致即拒绝。

共享视图里的 `settings` 表示启动选择；顶层 `model/modelProvider/reasoningEffort` 仍只记录原生响应确认值。初始未建立 S1 时不把选择宣称为已运行。原生返回不一致时暂停，保存已返回的 thread ID 并阻止继续提交或重复创建；恢复失败会关闭未完成核对的运行进程，不能通过点击恢复绕过核对。原生模型调用报错也不会换模型重试。

此前版本的分身若已有完整确认值，升级后固定为该组值；缺少完整确认值则暂停，需新建并选择。此设置固定的是模型标识、Provider 标识与推理强度，不快照认证信息、Provider endpoint 或全部原生配置；hooks、插件、MCP 及 Provider 定义仍按当前原生配置加载。模型别名的服务端更新和账户可用性不属于可固定的模型版本保证。

## 连续聊天与 Session

| 对象 | 职责 |
| --- | --- |
| C1 / `shadowId` | 持久共享对话；保存作者、消息、当前段指针及相关记录 |
| S1、S2 / 原生 thread | 主会话的先后两段，处理消息、短回答、任务协调和结果汇总 |
| W / 原生 thread | 从派发时创建的独立后台工作会话；长任务不占住主会话等待 |
| J / job | Core 中任务目标、来源、版本、工作 thread、状态及结果事件；属于 C1，跨段保留 |
| T / topic | 活跃、暂放或完成的话题和约束；不是 Session 路由 |
| CM / 短原生 thread | 预算附近提出 compact 或 switch 建议 |
| M / 短原生 thread | 空闲时按新增消息批次提出记忆候选 |

首条消息或首次需要行动的成员动态接续创建 S1；普通观察可使用短 thread 而不创建主段。改变话题、另一位成员发言、普通追问都继续进入当前段，不先运行“新问题/追问”分类器。歧义由当前 Agent 利用历史澄清。Core 的作者封装是分身语义，不改变现有共同执行原文输入规则。

每个分身有一个专属 app-server；不同分身互不接管。主轮仍是单轮执行，后续输入排队，后台并发默认为 2。后台会话使用同一 Harness 的独立 thread，未采用依赖父 S1 存活的原生子 Agent，也不假称把原生子 Agent 迁入 S2。

## 上下文与换段

原生压缩保持启用。Core 使用原生报告的本轮输入/输出用量及上下文窗口估算余量，预留窗口的 1/8；当前初始 CM 预判线为可用部分的 80%，间隔至少 15 秒，增长水位抑制重复判断。这些是可调整实现参数，需由回放 eval 校准，不是延迟或质量保证。原生未报告窗口时不编造精确用量，继续依赖原生压缩并在状态中说明。

CM 读取近期原话、未决话题、任务版本及真实状态，只返回建议。Core 在主轮、工具和审批已经结束的边界执行：

- `compact`：调用 `thread/compact/start`，仍用 S1，摘要由原生生成。
- `switch`：先让 S1 写交接笔记，再创建 S2，用当前持久状态和笔记进行接手轮次；收到 `HANDOFF_READY` 后才原子更新当前段指针，之后取消 S1 的订阅。

交接期间继续接收并持久保存成员消息，投递在 S2 接手后继续。W 的原生 ID 与 J 的版本不变，结果始终交给 C1 当时的主段。原生自动压缩完成会推进压缩代次，并等待新的原生用量报告，避免用压缩前读数反复触发；段、代次或消息数量发生变化后，旧 CM 决定失效。接近保留预算时暂缓新输入，CM 失败、无效或超时按当前状态回退到原生压缩；维护轮超过 90 秒后忽略晚到决定，并向已知原生轮次请求停止。

近期原文和工作状态是有界投影，完整记录可通过 `shadow_history`/`shadow_recall` 回读。首版最多 32 个排队或执行中的任务、30 个未结束话题，主上下文保留它们的索引和摘要；已结束任务只保留近期摘要。历史检索目前是本地文本扫描，不宣称大规模语义检索。CM/M 完成后取消订阅，原生历史留存。

## 记忆与一致性

显式“记住、改成、忘掉”由主轮调用 `shadow_remember` 后才确认。个人记忆归属该消息作者；空间记忆面向全空间。现有记忆修改需要 ID 和基准 revision，其他成员不能修改某人的个人偏好。每次成功保存推进版本并记录来源；纠正覆盖当前值，忘掉清空有效值并保留 tombstone。下一轮带入变化，换段从当前有效记忆接手。

忘掉意味着不再作为有效记忆使用，不会删掉聊天原文或原生历史。保留原始证据用于追溯，不能承诺擦除模型已经看到的内容。

M 在闲置 45 秒且至少有 4 条新增消息时开始，每批最多 20 条、最多 6 个候选。成功解析、来源核对且记忆版本未变化才提交候选和处理水位。成员的显式更正优先，过时整理结果不覆盖新值。候选保持未确认，不自动注入有效记忆；用户可以通过对话明确确认或拒绝。

## 后台任务与恢复

`shadow_task` 持久保存 J 后派发 W，主轮随即结束等待，成员可以继续交谈。工作会话获得原始成员要求、任务版本、必要上下文与来源，使用继承的原生能力。任务变更递增版本，先请求停止旧轮，确认完成/中断后再在同一 W 接续；取消区分 stopping 和 cancelled。旧版本及取消后晚到结果不能成为有效完成结果。

任务保存完成条件、独立进展 revision、检查点和准确依赖。`checkpoint` 保存进展；`wait` 保存讨论问题、请求、子任务或明确检查时间并进入 waiting；原生回合结束后释放工作槽。`finish` 明确提交 completed/needs_input/needs_followup/failed，completed 需要逐项完成条件核对且没有未解决依赖或问题。原生 final 本身只表示本轮结束；未提交业务结束的成功回合进入 needs_followup，由协调轮决定后续工作。

`shadow_task ask` 把实际提问与后续任务放在同一份持久记录中，成功存盘后才复用 `reply_to_annotation` 或 `add_annotation` 发送。现有任务传当前 version/revision；直接回合也可以同时创建 waiting 的 coordination/work 任务。记录包含实际正文、提及成员、答复条件、下一步、准确来源及任务关系，`questions` 返回有界索引或指定问题。运行中的 W 可以先做独立工作，再显式 wait；新建等待任务在回答到达后自动接续。

`ask` 的 `question.respondsTo` 明确新提问推进的原讨论问题，和发往哪里、引用哪些材料分别记录。多问题工作新开讨论时需要明确来源，独立问题可传空数组；实际 replyTo 目标始终保留，总共最多八个准确问题。显式来源在锁外读取核对，保存短摘录；发送前仍核对任务版本和本人接回状态。关系与提问、任务、发送意图同时落盘，丢失回执后的重试沿用原关系，不按后来的工作重新推断。普通公开回复工具继续用于直接事实答复，本文不把未登记的消息自动解释成任务。

本人成员可在本机分身的“记忆与任务”中查看“提问与接续”。索引默认显示关联未结束任务的提问，可查看历史；详情按需读取原问题关系及每项任务的条件、状态和下一步。答复到达、依赖满足与任务结束分别显示；未确认发送时不把回复父项当作已发问题。列表及关联条件分别分页并核对版本，总响应有界，查看来源保持人的已读状态。入口只读取所属成员的本机记录，不把原生会话身份、完整任务提示词或传输账本加入共享 View。

提问的 pending/unknown/saved 只表示发送确认，与答复到达、答复充分和任务完成分别记录。回执丢失时，Core 按原 requestId、真实 shadow/member 作者和讨论范围只读查回原问题；不自动重新发问。答复先于回执到达时，来源绑定与答案接收一起保存。相同提问 ID 不能改换正文或任务，同一实际问题可以被另一个任务按 questionId 明确引用。来源核对和依赖投递细节不进入共享视图。实现见[提问记录](../../../../internal/shadow/task_questions.go)与[准确来源核对](../../../../internal/collab/shadow_dependencies.go)。

等待只读取已登记的业务对象，不调用模型轮询，也不依赖成员未读列表。讨论依赖按原提问及后续回复链分批读取，覆盖本人自己的答复及先于 wait 到达的答案；请求、子任务结果和到期检查同样按稳定身份唤醒。答复到达只将任务重新排队，工作轮判断是否充分并引用实际信号解除对应依赖。部分答案可以推动独立工作，其他依赖继续等待；重复来源、等待环、过时目标和取消后的晚到答复不创建重复工作。读取并发有界，网络等待不占住主聊天调度。

工具注册未变化时，work 任务回准确 W；coordination 任务在当前主段串行接续。任务的真实来源可为成员消息或动态事件，工作轮、结果轮和接续轮均能更新任务、话题和开展正常协作；长期记忆仍需要实际成员表达记住、更正或忘掉。主聊天只带任务索引，完整要求与答复信号通过 `shadow_task status` 指定 id 回读。

W 的进展或结果先持久化为唯一事件，再由当前主段协调。成员消息发起的工作可生成共享回复；动态发起的工作通过原讨论工具发布实际答复，其内部 final 不追加到共享聊天。相同工具调用、消息 ID、原生完成事件和任务结果事件均去重。结果投递失败保留状态供核对，不自动重复已提交的通知轮。

Core 在创建或提交原生请求前保存意图。重启或连接断开后恢复准确 thread ID，用 turn ID 或原文中的专用运行标记核对已提交轮次；结果不明保持 unknown，不自动再次 `turn/start`。等待任务收到新答复后自动接续；已确认中断、失败或需要后续工作的任务可由协调轮根据原目标 resume/update，先核对已做行动，无需再次申请普通接续许可。

原生 thread 创建回执丢失且未得到准确 ID 时暂停并保留现场，首版没有猜测最近会话或自动新建的恢复捷径。原生异常、模型服务限制和工具审批可能影响可用性；应用“在线”不等于工具都可用。

动态工具由 `thread/start` 注册，`thread/resume` 不接受新增工具列表。Core 保存主段和工作会话的工具注册摘要；旧记录缺少摘要或工具变化时，在有实际工作且原生轮次/审批结束后升级。主段沿用交接笔记与 `HANDOFF_READY` 的换段流程；后台任务保留同一 J、目标版本、检查点、依赖、已做行动及最近原生结果，在新的 W 注册工具，并持久保留原 W 的身份与历史。工具不变时重启继续原 thread；未知原生输入先核对，升级不重放旧业务输入。交接失败保留原段并暂停，不循环花费模型轮次。实现见[工具注册与交接](../../../../internal/shadow/toolsets.go)。

## 成员动态接手与协作工具

本空间本人的最早自建分身作为稳定默认路线，新建其他分身不抢占；成员 Core 复用成员动态日志消费 @、直接回复、本人结果和关注变化。接收前保存独立队列与路线，确认后仍保留逐对象处理状态。人的已读不推进分身水位，已读事件的保留也计入尚未接收的分身消费者。暂停或离线保留信号，改选路线转交未开始的工作，在途工作保留实际归属。

分身列表中“接手我的动态”展示本人创建的分身，直接选择即可修改默认路线。读取不创建路线、不启动模型；变更使用 revision 和稳定 requestId，结果不明保留同一命令。旧命令的回执不能覆盖后来已生效的选择。选择可指向仍登记但当前本机不可用的本人分身，待处理记录保留；是否可处理依据 Core 的实际运行状态，不能以空闲时尚未启动原生 app-server 推断分身离线。已开始的任务与答复继续归属原处理分身。

个人动态按准确事件显示分身已接收、正在处理、已处理、关联任务已完成、等待或待本人回答；同一讨论的新事件不继承旧任务的完成。列表只带简短状态，展开时读取该事件关联的任务与行动回执。发送回执是历史业务受理事实，不等于对方已完成；原生回合结束也不自动完成任务。处理详情及其来源阅读保持人的已读状态。私有任务索引、错误和处理状态不加入共享空间视图、远端缓存或公开讨论。

已登记任务的答复优先进入原任务；直接 @ 或具体回复可在一个接续回合中读取、行动并保存认识；普通关注按对象合批观察。同一事件只走一条主要路径，任务读取与动态消费共用持久接收身份去重。直接处理提交前再次核对等待关系，覆盖排队期间才登记的依赖。原文读取和依赖路由异步进行，慢来源或局部失败不阻塞普通聊天。

直接处理的最终认识若写 continue，必须对应实际登记或本轮修改的未结束任务；needs_owner 必须对应已确认发出、提及本人的未解决问题。Core 从实际任务和提问记录生成关联证据，不接受最终文字自己声称“已安排后续”。无登记的后续说明保留为失败认识，已经发出的动作及真实任务仍保留；不自动重复该回合。no_action 只结束本轮理解，不会把已存在的任务改成 completed。认识记录保存有界的关联任务与提问 ID。

每批读取精确原文、父项与固定材料版本，实际正文前缀决定处理范围。直接回合可引用其已成功读取的额外来源，不能凭最终文字补造证据。材料撤回以来源失效处理，不为了处理旧事件重新披露已撤回正文。内部认识、收件原因和依赖投递回执留在成员 Core，不自动发布到 C1；已送入任务也不等于已理解或已完成。

本人修改已有关注对象时，普通观察和直接处理包包含 memberId 与准确的 memberChanges 来源，保留原始 human 作者；已登记问题的答案优先按任务依赖接续。分身据此更新事实和剩余问题，避免将本人已经完成的工作再当成新要求。分身自己的已知写入不通过该通道再次唤醒自己；这些事实同步不改变人的未读或已读。

分身附加现有公开读取、批注回复、成员目录、空间请求、顺流留言及分身聊天工具。Core 记录真实 shadow 作者和所属 memberId，日常协作不逐次询问发送许可。公开写入先保存稳定 requestId/messageId 对应的行动记录，跨轮重试核对同一业务对象；实际原生权限沿用配置。分身临时咨询不扩大本人的永久关注。

关注保存生成私有初始化信号，读取当时固定的有界来源；讨论包含根项和最多八条近期回复。来源实际读取成功后才进入认识证据，空会话不伪造历史，初始化不改变人的未读。关注取消与父对象静音按成员 Core 接收到的当前偏好重新核对未开始的普通分析。

`shadow_watch` 在所属成员发起的对话或任务中提供 read/list/start/update/pause/resume/complete；其他成员共享请求使用公开来源及其实际任务。start 复用现有成员关注并初始化同一对象，目标修改独立使用 goalVersion，普通认识更新使用 revision。暂停保留已接收队列，恢复继续；完成只结束明确目标，后续普通变化仍可更新认识，不能据此重做旧目标。改变目标会阻止旧目标版本调用 Team Cross 协作写入，已经明确委托且独立于该认识的任务不被取消。写入先持久保存真实消息来源和稳定 requestId；远端关注回执丢失后核对同一业务命令，重复已确认命令不重新开启后来被本人取消的关注。列表只带有界索引，完整认识按准确 id 读取；这些步骤均不增加逐次确认对话。

任务另存私有 follow 目标绑定，真实触发来源仍保留。普通关注派生任务及其子任务默认绑定；直接 @ 和独立成员委托默认独立，start 可用已有 followId 显式关联。绑定目标变化递增任务 version，先持久停止意图，再向准确原生 turn 请求中断；回执只证明请求受理，实际终止后才进入 paused、排队重核或 cancelled。检查点、动作与答复信号跨暂停和重启保留；恢复后同一 W 调用 `shadow_task replan` 保存当前要求、完成条件及要保留的依赖，再继续行动。目标结束只取消未结束的绑定工作，不替代完成条件核对。来源引用不会把独立委托变成随一般关注停止的任务。实现见[关联任务目标控制](../../../../internal/shadow/task_follows.go)。

任务可另用 relatedFocuses 关联最多八个已存在的认识对象，每项记录具体用途，与唯一 follow 目标控制分开。Core 保留每项最后核对的事实和当前事实；有变化时让等待中的同一 J/W 接续，普通接续包只展开变化项。contextReviews 按任务返回的准确认识 revision 保存影响说明；未核对的新认识不能被 wait 或 completed 丢弃。也可等待这些明确关联认识的新变化，等待期间没有模型轮询。已向当前原生轮提供的事实有持久输入记录，模型遗漏核对会保留 needs_followup，不凭同一份未核对内容无限自动重跑。

认识快照每份最多 3 KiB，截断标记 partial，准确来源 ID 不截断；必要时按任务 status 或原文继续读取。私有 follow 目标、内部内容指纹和关联清单不进入共享任务 View，主上下文只保留任务索引。观察包可见同成员、同空间仍在使用该对象的任务摘要，包括旧默认分身的任务，以便更新认识后让既有工作继续。relatedFocuses 默认使用 live：Core 按登记对象读取原始业务变化，普通关注取消或静音不切断独立任务的来源。mode=snapshot 固定登记时的认识和证据，之后不跟随新事实，也不进入活跃来源查询；它不改变原任务目标。实现见[任务关联认识](../../../../internal/shadow/task_contexts.go)和[任务来源接收](../../../../internal/shadow/task_sources.go)。

任务来源查询只带准确 subject 和 seq/retention 位置，空间主机核对本人成员与分身归属，返回最多十六项实际事件。材料包含版本和其讨论，会话包含准确终态轮次及其讨论；本人业务写入同样可见，偏好控制信号不进入此通道。cursor 与待处理信号同次保存，一页认识尚未合并前不继续取下一页。暂停保留位置，恢复补齐；完成、取消或移除关系后，晚到读取不再改变任务。查询异步且最多四项并发，按最近完成时间公平安排；不会占用模型等待轮。

原始变化通过已有 understand 写回同一对象的认识，再由各任务核对自己的影响；普通观察和任务共享准确事实回执，已理解的排队普通事件无需再观察，直接问题仍保留行动入口。读取失败不推进位置，来源日志发生压缩时返回明确的不完整重建信号和有界当前来源，认识合并后仍保存 historyGap，不宣称缺失历史已经审阅。新变化在 wait 后、原生轮结束前到达时接续原 W；已提供但未核对的同一输入保留 needs_followup，不无限自动重跑。来源、游标、错误与关系不进入共享任务 View。来源桥接见[本机及跨 Core 查询](../../../../internal/collab/shadow_task_sources.go)。

已被原任务直接接收的答复由该任务回写认识，不另派一轮协调。任务 status 和工作包给出有界 understandings，按实际答复对象、原触发对象和已登记问题的 respondsTo 定位；此前没有认识时可建立同一对象的初始事实。工作轮调用 `shadow_task understand`，保留仍有效的旧结论、合并实际答复、更新剩余问题，并引用本次答复依据。认识、所覆盖答案和稳定命令回执在成员 attention 记录中同次保存；失败不提前消费，重启后同 requestId 取得原结果。未回写的答复不能被 wait 或 completed/needs_input 丢弃，更新认识也不会自动满足任务条件，依赖仍需 resolutions 核对。

认识回写按准确 revision 比较更新，最多一次处理八个对象、每对象十六个明确答复 ID；剩余目标可继续回读。更新后，使用该认识的其他活跃任务沿原关联接续。若旧观察或直接回合随后结束，其过时认识不会覆盖新事实；原业务动作保留，输入改为普通观察重新核对最新事实，不自动重做直接回复。过程不改人的已读，不将认识正文或内部回执加入共享任务 View。实现与回放见[答复认识回写](../../../../internal/shadow/task_understanding.go)及[测试](../../../../internal/shadow/task_understanding_test.go)。

分身可通过 update_space_brief 按条目维护议题、决定与建议、问题和进展，沿用真实 shadow/member 作者、稳定行动和准确来源。并发修改返回最新修订，由分身合并；普通写入无需逐次人工确认。read_space_brief 支持历史修订、单条目和保存命令回执，回执明确 readBack 工具；准确历史来源可进入任务证据和动态来源读取。条目状态、历史保留和界面行为由[空间简报契约](space-workbench.md#空间简报)维护，实现见[简报读写](../../../../internal/collab/workbench_brief.go)。

问题级本人接回、成员等待页、默认分身选择和个人动态中的处理状态已在独立分支接通，日常交接及默认选择不增加第二次确认。准确任务结果顺流、证据变化后的针对性更正仍待补齐。首次关注与目标管理已有工程回放和受控来源的真实模型证据；关联任务控制的具体验证见实施记录，不等于跨 Core 产品界面已验收。已登记依赖的分流不等于所有尚未登记的跨分身提问都已建立业务关系；完整问题闭环仍需继续验证。进展见[实施记录](../../tasks/2026-10-24-shadow-activity-implementation.md)。

## 固定消息与任务结果来源

分身消息通过稳定消息 ID 回读，已同步正文、作者、父消息和原始时间不能被后续同步覆盖；送达与处理状态仍可以推进。任务结束时，在同一次持久替换中保存独立的 `TaskResult`，包含结果 ID、任务及目标版本、原请求来源、实际 outcome、完成条件核对、检查点及证据。原生 final 未满足业务完成条件时仍保存为 needs_followup。更新任务、接续或换段不改写已有结果正文。

每个分身保留最近 256 份任务结果。共享读取默认只提供最近 20 份结果索引及总数，正文通过 `read_space_shadow(messageId|resultId)` 或准确来源接口按需读取；来源沿用 `SpaceSourceRef` 的 `shadowId` 与 `shadowMessageId`／`shadowResultId`。结果超出保留范围时明确不可用，不用当前任务结果替代旧引用。这个保留范围是来源回读窗口，不能作为尚未实现的任务回传必达保证。

固定来源可作为简报及任务证据，读取不推进人的已读。任务结果快照与通知送达分别记录；此来源能力本身不建立原工作会话返回路线，准确顺流回传继续按实施记录推进。

## 送达、权限与停止

空间主机短暂保存投递尝试，只有运行分身的 Core 完成持久写入并回传后才标为“已送达”。这不等于模型完成。离线、暂停或投递超时显示未确认送达，用户手动重发同一 ID 和原文；回执丢失也不会再执行已有输入。不增加云端信箱、离线自动补发或成员自动广播。

原生审批和工作目录诊断只在运行分身的本机可见、可处理；普通成员只能读共享聊天、记忆与任务。暂停接收会保留正在执行的工作，恢复后继续处理已接收队列。明确获知成员撤销或空间关闭时停止该分身拥有的运行进程，未知轮次待原生核对；瞬时网络失败不取消已接收工作。关闭 Core 仅停止它管理的分身进程，不关闭用户其他 Codex。

插件面板更新沿用[草稿恢复契约](chatgpt-local-plugin.md)：按 Core、空间、分身和原生请求隔离，保留未发送正文、创建表单及结果不明的创建请求 ID；刷新不自动创建、重发消息或提交审批。恢复后仅能显式重试同一请求。

Core 检测到已安装新构建时，分身正在接收的队列、换段和后台任务，以及活跃原生轮次、压缩与审批共享最多 10 秒的收尾时间；暂停接收不会掩盖仍在运行的工作，也不能无限期阻止升级。到期正常关闭 Core 托管运行时，保存待核对状态；实际进程退出与新服务启动另需耗时。空闲原生进程、已暂停的持久队列和没有存活运行时的未知轮次不消耗收尾时间，恢复后仍核对原生状态，不自动重放未知输入。具体切换和插件按需启动规则见[分发与生命周期](../distribution-and-onboarding.md#启动发现与退出)。

## 问题回复交接与成员等待

成员 Core 按准确 `spaceId/executionId/annotationId/replyId` 保存本人和分身的回复分工，记录由本人成员持有，跨默认分身变更保留。原问题详情里的“这条我来／交回分身”直接写入版本化交接；自然语言通过 `shadow_task handling/handoff` 操作同一记录，只有实际本人来源能改变自己的回复分工。其他成员的普通协作请求照常推进，不被视为本人接回。

接回只停止对应问题未提交的代答或追问，保留调查、已有任务及已发送消息；混合任务可继续处理其他准确问题。发送意图与接回操作按同一个本机记录锁排序，接回前已提交的网络写入可能仍送达，不能称为已撤回。准确回复目标始终核对；单一问题来源也覆盖另起讨论的追问。混合来源下新建讨论的明确问题关联仍需继续补齐，不能宣称所有表达形式均已防止重复代答。

本人答复通过原讨论的准确回复链增量读取，接回时固定已有回复位置；旧答复、同事发言和另一回复分支不代替本次本人回答。读取不运行模型，未读状态不参与判定。已观察到本人回答只是事实证据，原任务仍需核对各依赖条件。交回保存内部接续及当前问题、已有答案，不制造空间事件或 C1 用户消息。普通关注暂停或目标变化不取消明确交回的问题；旧回合的认识不会覆盖新关注目标的认识。

“我的动态”提供“别人等我／我等别人／待接续”，由本人在同空间所有本机分身的任务依赖与问题分工生成。问题按准确来源合并，逐任务保留等待条件；未确认发送的提问不链接成父问题，也不显示为对方已经欠一个答案。答复已到但尚待核对的项进入待接续；打开列表不启动新分析，也不标记通知已读。索引分页绑定实际内容版本，当前最多返回 50 项、每项展示前 16 项关联条件并报告总数。实现入口：[问题交接](../../../../internal/shadow/question_handling.go)、[等待投影](../../../../internal/shadow/waiting.go)、[本机接口](../../../../internal/collab/shadow_handling.go)。
