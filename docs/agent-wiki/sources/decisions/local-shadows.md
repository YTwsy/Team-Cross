# 本机数字分身

本页维护分身的共享范围、上下文、记忆、后台任务与恢复契约。首版接入本机 Codex；Claude 后续适配，不提供对话中途更换 Harness。实现入口为 [shadow](../../../../internal/shadow/)、[空间桥](../../../../internal/collab/shadows.go) 和 [聊天界面](../../../../packages/web/src/components/SpaceShadows.tsx)。实际验收范围见 [证据入口](../validation/evidence-map.md#本机数字分身)。

## 空间与运行归属

空间中的成员可以在自己的 Mac 上创建分身，明确指定名称和工作目录。一个分身只属于一个空间；同一分身只有一条持续共享的聊天，整个空间可读、可参与，新成员按现有空间规则阅读历史。消息作者来自经核验的成员凭据，客户端不能指定其他作者。

空间主机保存共享视图，运行分身的成员 Core 保存原文、任务、记忆、交接与原生投递账本。运行留在创建者的 Mac。这与现有共同执行的 fork、输入交接和原生直接客户端分别管理：所有成员可以向分身发送普通消息，Core 串行投入当前主会话；成员不因此取得原生控制或审批权限。

首版通过独立 app-server 使用本机有效 Codex home 和工作目录，不裁剪原生模型路由、认证、权限、MCP、插件、hooks、skills 和记忆加载配置，不改用户配置文件。分身的动态工具是附加能力。原生工具可能访问工作目录以外的资源，分身不构成额外只读沙箱；创建页面说明共享输入范围。模型和推理强度在创建时选择一次；产品不固定套餐或模型。

现有私人会话 P0 不会被 fork 或自动读入。原生配置中明确启用的个人记忆仍按原生规则加载，不能把“未导入 P0”说成完全隔离个人资源。

## 启动模型配置

创建表单根据工作目录读取本机 Codex 的有效 `config/read` 和完整分页 `model/list`，预填当前模型、Provider 和推理强度。用户选择模型和该模型公布的推理选项；Provider 沿用当前原生路由，不另加套餐或账户选择。读取模型列表只启动短期元数据进程，不创建原生 thread、不发送模型输入；结束后关闭进程。未在目录中的已配置自定义模型仍保留，能力未知时要求明确填写推理强度，并由原生创建响应核对，不替换成其他模型。

Core 在创建分身时持久保存不可变的 `settings:{model,modelProvider,reasoningEffort}`。首次 S1、后续 S2/Sn、独立 W、CM、M 的 `thread/start` 和重启的 `thread/resume` 全部显式应用这组值；各 `turn/start` 再传相同 model/effort。暂停/恢复、换段、后台任务更新或重启均不重新读取模型默认值，不提供逐消息选择或运行中修改入口。创建重试沿用同一 requestId 和完整 settings，设置不一致即拒绝。

共享视图里的 `settings` 表示启动选择；顶层 `model/modelProvider/reasoningEffort` 仍只记录原生响应确认值。初始未建立 S1 时不把选择宣称为已运行。原生返回不一致时暂停，保存已返回的 thread ID 并阻止继续提交或重复创建；恢复失败会关闭未完成核对的运行进程，不能通过点击恢复绕过核对。原生模型调用报错也不会换模型重试。

此前版本的分身若已有完整确认值，升级后固定为该组值；缺少完整确认值则暂停，需新建并选择。此设置固定的是模型标识、Provider 标识与推理强度，不快照认证信息、Provider endpoint 或全部原生配置；hooks、插件、MCP 及 Provider 定义仍按当前原生配置加载。模型别名的服务端更新和账户可用性不属于可固定的模型版本保证。

## 连续聊天与 Session

| 对象 | 职责 |
| --- | --- |
| C1 / `shadowId` | 持久共享对话；保存作者、消息、当前段指针及相关记录 |
| S1、S2 / 原生 thread | 主会话的先后两段，处理消息、短回答、任务协调和结果汇总；S1 就是首条消息的处理会话 |
| W / 原生 thread | 从派发时创建的独立后台工作会话；长任务不占住主会话等待 |
| J / job | Core 中任务目标、来源、版本、工作 thread、状态及结果事件；属于 C1，跨段保留 |
| T / topic | 活跃、暂放或完成的话题和约束；不是 Session 路由 |
| CM / 短原生 thread | 预算附近提出 compact 或 switch 建议 |
| M / 短原生 thread | 空闲时按新增消息批次提出记忆候选 |

首条消息才创建 S1；改变话题、另一位成员发言、普通追问都继续进入当前段，不先运行“新问题/追问”分类器。歧义由当前 Agent 利用历史澄清。Core 的作者封装是分身语义，不改变现有共同执行原文输入规则。

每个分身有一个专属 app-server；不同分身互不接管。主轮仍是单轮执行，后续输入排队，后台并发默认为 2。后台会话使用同一 Harness 的独立 thread，未采用依赖父 S1 存活的原生子 Agent，也不假称把原生子 Agent 迁入 S2。

## 上下文与换段

原生压缩保持启用。Core 使用原生报告的本轮输入/输出用量及上下文窗口估算余量，预留窗口的 1/8；当前初始 CM 预判线为可用部分的 80%，间隔至少 15 秒，增长水位抑制重复判断。这些是可调整实现参数，需由回放 eval 校准，不是延迟或质量保证。原生未报告窗口时不编造精确用量，继续依赖原生压缩并在状态中说明。

CM 读取近期原话、未决话题、任务版本及真实状态，只返回建议。Core 在主轮、工具和审批已经结束的边界执行：

- `compact`：调用 `thread/compact/start`，仍用 S1，摘要由原生生成。
- `switch`：先让 S1 写交接笔记，再创建 S2，用当前持久状态和笔记进行接手轮次；收到 `HANDOFF_READY` 后才原子更新当前段指针，之后取消 S1 的订阅。

交接期间继续接收并持久保存成员消息，投递在 S2 接手后继续。W 的原生 ID 与 J 的版本不变，结果始终交给 C1 当时的主段。原生自动压缩完成会推进压缩代次，并等待新的原生用量报告，避免用压缩前读数反复触发；段、代次或消息数量发生变化后，旧 CM 决定失效。接近保留预算时暂缓新输入，CM 失败、无效或超时按当前状态回退到原生压缩；维护轮超过 90 秒后忽略晚到决定，并向已知原生轮次请求停止。

近期原文和工作状态是有界投影，完整记录可通过 `shadow_history`/`shadow_recall` 回读。首版最多 32 个排队或执行中的任务、30 个未结束话题，主上下文保留它们的索引和摘要；已结束任务只保留近期摘要。历史检索目前是本地文本扫描，不宣称大规模语义检索。CM/M 完成后取消订阅，原生历史留存。

## 记忆与一致性

显式“记住、改成、忘掉”由主轮调用 `shadow_remember` 后才确认。个人记忆归属该消息作者；空间记忆面向全空间。现有记忆修改需要 ID 和基准 revision，其他成员不能修改某人的个人偏好。每次成功保存推进版本并记录来源；纠正覆盖当前值，忘掉清空有效值并保留 tombstone。下一轮带入变化，换段从当前有效记忆接手。

忘掉意味着不再作为有效记忆使用，不会删掉聊天原文或原生历史。保留原始证据用于追溯，不能承诺擦除模型已经看到的内容。

M 在闲置 45 秒且至少有 4 条新增消息时开始，每批最多 20 条、最多 6 个候选。成功解析、来源核对且记忆版本未变化才提交候选和处理水位。成员的显式更正优先，过时整理结果不覆盖新值。候选保持未确认，不自动注入有效记忆；用户可以通过对话明确确认或拒绝。

## 后台任务与恢复

`shadow_task` 持久保存 J 后派发 W，主轮随即结束等待，成员可以继续交谈。工作会话获得原始成员要求、任务版本、必要上下文与来源，使用继承的原生能力。任务变更递增版本，先请求停止旧轮，确认完成/中断后再在同一 W 接续；取消区分 stopping 和 cancelled。旧版本及取消后晚到结果不能成为有效完成结果。

W 的结果先持久化为唯一事件，再由当前主段生成共享回复。相同工具调用、消息 ID、原生完成事件和任务结果事件均去重。结果投递失败保留状态供核对，不自动重复已提交的通知轮。

Core 在创建或提交原生请求前保存意图。重启或连接断开后恢复准确 thread ID，用 turn ID 或原文中的专用运行标记核对已提交轮次；结果不明保持 unknown，不自动再次 `turn/start`。已确认中断/失败的任务可由用户明确要求接续；不自动重跑潜在副作用。

原生 thread 创建回执丢失且未得到准确 ID 时暂停并保留现场，首版没有猜测最近会话或自动新建的恢复捷径。原生异常、模型服务限制和工具审批可能影响可用性；应用“在线”不等于工具都可用。

## 送达、权限与停止

空间主机短暂保存投递尝试，只有运行分身的 Core 完成持久写入并回传后才标为“已送达”。这不等于模型完成。离线、暂停或投递超时显示未确认送达，用户手动重发同一 ID 和原文；回执丢失也不会再执行已有输入。不增加云端信箱、离线自动补发或成员自动广播。

原生审批和工作目录诊断只在运行分身的本机可见、可处理；普通成员只能读共享聊天、记忆与任务。暂停接收会保留正在执行的工作，恢复后继续处理已接收队列。明确获知成员撤销或空间关闭时停止该分身拥有的运行进程，未知轮次待原生核对；瞬时网络失败不取消已接收工作。关闭 Core 仅停止它管理的分身进程，不关闭用户其他 Codex。

插件面板更新沿用[草稿恢复契约](chatgpt-local-plugin.md)：按 Core、空间、分身和原生请求隔离，保留未发送正文、创建表单及结果不明的创建请求 ID；刷新不自动创建、重发消息或提交审批。恢复后仅能显式重试同一请求。

Core 检测到已安装新构建时，分身正在接收的队列、换段和后台任务，以及活跃原生轮次、压缩与审批共享最多 10 秒的收尾时间；暂停接收不会掩盖仍在运行的工作，也不能无限期阻止升级。到期正常关闭 Core 托管运行时，保存待核对状态；实际进程退出与新服务启动另需耗时。空闲原生进程、已暂停的持久队列和没有存活运行时的未知轮次不消耗收尾时间，恢复后仍核对原生状态，不自动重放未知输入。具体切换和插件按需启动规则见[分发与生命周期](../distribution-and-onboarding.md#启动发现与退出)。

## 验证边界

动态工具使用 Codex app-server 实验接口；接入版本升级需要重新验证。首版工程回放、真实 Codex 和空间传输的证据分别记录，不以模拟测试代替模型效果，也不把单 Mac 多 Core 当成多 Mac。继承配置的结构检查与具体插件、hooks、电脑控制、第三方模型可用性分别取证，不能从一个测试 MCP 推导所有组合已通过。

复验入口、故障情形与 eval 改动要求见 [验证门槛](../validation/test-gates.md#本机数字分身)；当次结果和限制见 [实现记录](../../tasks/2026-10-21-local-shadow-design/implementation.md)。
