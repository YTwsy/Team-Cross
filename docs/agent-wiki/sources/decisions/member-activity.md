# 成员关注与动态

本页维护成员关注材料、讨论和协作会话，以及 @、回复提醒和已读同步的当前契约。字段、路由和限额见[协议](../protocol.md#成员动态接口)，实际被测范围见[证据入口](../validation/evidence-map.md#成员动态)。原始方案与布局修正见[设计记录](../../tasks/2026-10-23-member-activity-design.md)。

## 入口与视觉

全局主导航提供“我的动态”，聚合本机已发起／加入且仍有访问权的空间。空间内在**空间概览页面正文**的首屏展示“最近动态”，默认最近三组，原位展开完整列表；不增加空间侧栏导航项。概览切换“与你有关／空间全部”，全局只汇总个人提醒。个人列表可按全部、@我、回复、关注、仅未读及空间筛选。

动态区复用既有页面排版、留白、分隔线、头像、文字按钮及主题变量；浅色、深色与中英语言遵循本机界面设置。材料和协作会话标题、讨论头部提供关注入口，动态区提供管理关注。收藏、阅读与关注分别保存。

## 身份与关系

`mentions` 由成员选择生成，包含空间成员 ID、显示名及正文 UTF-16 范围。服务端核对正文和有效成员，普通粘贴 `@名字` 不产生提及。离线但资格有效的成员仍可选；成员已撤销时提交失败并保留草稿。同名成员以 ID 区分，@ 不改变访问范围。

回复保持同一根讨论中的平铺展示。`replyTo` 指向根批注或已存在的具体回复；只能指向同一根讨论内的项。具体回复可继续回复，显示父项短引文并定位；直接回复对象依据持久父项，不能按最后发言者猜测。未携带 `replyTo` 的已有单层调用仍明确回复根批注。

作者类型由 Core 写入。普通成员提交为 human，绑定运行时提交为 session；未知历史作者保留 unknown。会话作者没有经核实的所属成员时，不把回复猜配给空间发起者。@、明确直接关系及有效关注仍可独立匹配。

## 关注规则

材料以 `materialId` 关注，覆盖其所有固定版本及版本下讨论；讨论以根 `annotationId` 关注，会话讨论额外保留 `executionId`；协作会话以 `executionId` 关注，包含新轮次终态及其讨论。正文附带其他材料引用不改变讨论的主要归属。

新材料发布者自动关注材料，新评论／回复作者自动关注根讨论。创建或浏览协作会话、被 @、收藏和读取都不自动关注。首次启用以现有业务快照为基线，不把旧历史补成未读。手动关注、取消后再关注仅接收成功保存后的变化。

| 保存模式 | 普通更新 | 直接 @、直接回复、本人结果 |
| --- | --- | --- |
| following | 接收 | 接收 |
| direct_only | 不接收 | 接收 |
| muted | 不接收 | 不新增提醒 |

取消保存显式 direct_only，后续发言不能覆盖它。讨论自身的显式或自动偏好优先于普通父对象关注；父材料／会话静音优先于子讨论。取消父对象关注不取消独立讨论关注。解除静音恢复静音前模式，历史提醒不因此被删除。偏好保存带 revision 和 requestId，冲突先刷新，重试同 ID 不改变已确认结果。

## 事件、分组与已读

材料发布／更新／撤回、根评论／回复、协作请求终态、简报修订和协作会话终态生成带准确来源的事件。工具输出、token 流、过程发言、心跳不逐条生成成员提醒。原生无最终正文的完成状态显示“本轮已结束”。

成员本人发布的 human 内容不提醒本人。接收者在业务提交时根据成员资格与当时偏好确定；同一事件合并 mention、direct_reply、own_turn_result、own_request_result 和各级 follow 原因。既关注材料又关注讨论时保留两个原因，仍只有一份提醒。请求结果与公开回复没有可核实的同源身份时保留各自事件，不按文字或时间去重。

讨论、材料和协作会话分别按稳定对象分组。角标统计含未读的分组，行内显示未读条数。筛选先选底层事件再分组；分组优先定位未读 @，其次直接回复及本人结果，不让新普通回复遮住旧未读 @。每组近期展开最多二十项，较早正文可从来源读取。

点击动态先按固定来源读取实际内容，具体回复滚动到目标；成功加载且进入可见区域才确认所见事件。打开列表、后台加载、折叠或 Agent 读取均不确认人已读。原文讨论区也按实际可见根批注／回复确认。全局、概览、浏览器及同一成员的客户端共享主机已读记录；同机刷新事件与四秒查询更新视图。

显式“全部已读”只确认当前已取得快照的序号，不清除并发的新事件。各空间独立提交并报告失败，单组同样带快照。已读按单事件集合与只增不减的全局水位合并；普通读数不更改 Agent 投递、Cloud ack 或业务完成状态。

## 持久化与恢复

业务对象与待发布事件写入同一源记录；投递到空间日志成功后才清空 outbox。空间日志使用稳定事件 ID 去重，单调 seq 建立快照。失败保留可恢复事件并显示同步错误，禁止为补提醒重放业务正文。个人偏好、接收原因及已读状态不进入公共空间 View、材料发布包或运行时 MCP。

共同执行输入被接受前保存具体成员与请求身份，结果绑定原生 turn ID；后续输入权转移不改变结果接收人。补充输入等待接受结果后才发布终态提醒。历史回读只读取原生已保存轮次，首次建立基线，后续向已知边界追读；最多 125 页，未完成则报告同步异常。没有可验证成员关系的外部续写只供会话关注者查看，不猜测其发起者。

远端 Core 保存待同步已读动作及身份绑定的有限缓存。断线保留计数和精确定位元数据，标记“暂未同步”；缓存不保存事件正文预览。恢复只补交明确已读动作，快照之后的事件仍未读；重新加入不按同名继承旧状态。已确认撤权后清除缓存，队列不跨凭据迁移。来源弹窗持续重新核对权限，失败即清除已加载正文。

90 天前且已读／无个人未读的普通事件可压缩；未读及未确认 outbox 身份不按时间删除。过期或因已读变化而失效的分页游标要求重建列表，不重置已读。容量边界见协议，达到边界须保留既有数据并显示错误。

## 独立消费者与支持边界

成员关注不启用顺流感知、Cloud 订阅或本机分身持续关注，不启动模型或发送会话请求。现有消费者继续沿用自己的授权及投递进度，可引用相同空间／材料／讨论／轮次身份；本次没有把它们重写为一个消费队列。

当前 WebGUI、嵌入 WebGUI 的 UI 路由及个人 MCP 具有成员动态接口；运行时 MCP只能按原权限读取／回复公开讨论，不能管理或读取人的私人动态。真实原生、桌面宿主、跨机器及网络的验证范围只以证据入口为准；界面内列表不包含系统推送、邮件、@所有人或跨设备账号迁移。
