# 2026-09-10 WebGUI 上下文刷新验证

## 环境与范围

- macOS 14.8.5、Apple Silicon；Chrome 152.0.7977.83。
- Go 1.25.3、Node 24.18.0、pnpm 11.19.0、React 19.1.1。
- 基于 `main` 的 `389608e` 及当前工作区改动。Core 为本次重建的 `0.2.0-dev`，使用独立数据目录和本地监听，浏览器使用独立 Playwright 会话。
- 验证构建后的嵌入式 WebGUI，通过模拟 API 响应控制协作序号、延迟和新对话内容。未启动真实模型、TUI 或 Desktop，未进行两台 Mac 的 LAN 验证。

## 问题与修复

协作详情每 2.5 秒读取状态。原实现把 `sequence` 拼入上下文 URL，序号变化使 `useResource` 清空数据；上下文组件在任何加载期间都会用占位替换已显示的内容。页面因此暂时变短，对话及长消息的内部滚动容器也被重建。

同一上下文现在以独立的刷新参数重新读取，资源地址保持稳定；已有数据时继续渲染原内容，响应完成后原位更新。切换标签或文件仍按不同资源加载，较早的请求响应不会覆盖新结果。产品行为见 [上下文阅读](../product-flows.md#上下文阅读)。

## 浏览器结果

修复前在 1440 × 900 视口复现：等待刷新时，页面纵向位置由 604px 变为 181px；响应回来后，对话容器的 300px 和长消息的 70px 阅读位置均归零。

修复后覆盖邀请者／协作者、1440／1024／768 CSS 像素宽度、浅色／深色主题，共 12 种组合。每种组合均比较请求前、等待响应和新内容渲染后的页面高度及三层滚动位置：位置保持一致，原对话与消息节点保留，新内容正常出现，无页面水平溢出和未捕获脚本错误。已保存截图，并复核修复前占位、浅色桌面、深色中等窗口和浅色窄窗口的实际画面。

另在同一页面连续进行五次自动更新和一次手动刷新。三层位置始终保持页面 400px、对话 300px、长消息 70px，未出现加载占位或滚动归零。

本记录仅支持上下文刷新与滚动行为的结论，不将模拟协作扩大为原生客户端或跨设备验收。

测试结束后已关闭本次启动的 Core、Vite 和专用浏览器，并确认两个测试监听端口已释放。
