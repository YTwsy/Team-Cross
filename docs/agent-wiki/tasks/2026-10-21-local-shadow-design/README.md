# 本机数字分身：自然交流、分段、记忆与 Harness 设计

状态：用户已授权按本方案开始实现，先跑通 Codex。实现与验证进展见[实现记录](implementation.md)；设计演示不是运行验收证据。本记录承接[协作体验头脑风暴](../2026-10-16-collaboration-experience-brainstorm.md)。

直接用浏览器打开本目录的 [local-shadow-design.html](local-shadow-design.html)。它是完整的静态说明页，无外部运行依赖，不需要开发服务器或内联可视化宿主；按桌面阅读组织，不作为待交付的前端产品。

## 本轮明确的范围

- 像私聊机器人一样，在同一个窗口自然交流；不让用户手动选择“新问题”或“追问”。
- 对话面向整个协作空间共享：同一空间与同一分身共用连续对话 C1，空间成员可阅读和参与；消息保留发起者，不按成员拆成私人主 Session。不同空间的对话与 Core 管理的记忆范围分开。
- 话题切换不等于新建 Session；同一个 Session 可以包含多个话题，同一话题可以跨段继续。
- 演示作为仓库 task 保存；通过独立页面或文件打开，不嵌入 ChatGPT 会话预览。
- 先跑通本机 Codex 的完整流程，Claude Code 作为后续适配方向，不阻塞第一轮验收；不支持聊天中途更换 Harness。创建时选定 Harness 后，同一 Harness 内的 Session 换段和准确恢复仍然需要实现。
- Harness、模型路由与 Token Plan 分层：沿用本机已经配置并可用的模型、端点与认证，不按某家订阅或套餐设计分身；Team Cross 不另建直连模型的调用路径。
- 主 Agent 负责对话和协调，长调查交给后台工作 Agent；新消息不必等待整项后台任务结束。
- 首版全量继承所选本机 Harness 的有效配置，包括模型路由、认证方式、hooks、插件、skills、MCP、原生记忆加载方式和权限设置；不另建删减工具的分身配置。
- 保留原生压缩机制，同时保留轻量上下文管家 CM。CM 建议压缩或换段，Core 校验和协调，原生 Harness 执行自身压缩；首版不替换原生摘要算法。
- 不增加云端信箱或离线自动重发。分身所在 Mac 的 Core 持久接收后显示“已送达”；发送失败显示“重发”，由用户明确触发，同一消息复用 ID 去重。
- 默认工作仍是调查和分析，但全量继承后不宣称工具层强制只读或个人资源完全隔离。具体操作遵循用户指令与原生权限；继承配置不自动授权代替本人作出对外承诺。
- 设计演示保留供阅读；后续已进入 Codex 产品实现，当前行为由[分身契约](../../sources/decisions/local-shadows.md)维护，执行结果见[实现记录](implementation.md)。

## 推荐结构

| 对象 | 生命周期与职责 |
| --- | --- |
| 分身 B | 稳定身份、资料与工具范围；创建时选择本机 Harness |
| 空间共享对话 C1 | 同一空间与同一分身的持久消息流，面向空间成员共享；保存发起者、消息顺序与当前主 Session 指向，不与其他空间混用 |
| 主 Session S1 / S2 | 理解消息、快速回答、派发调查和汇总结果；C1 同时只有一个主 Session 接收用户新输入，但它不等待所有后台任务结束才接受下一轮 |
| 工作上下文 W1 / W2 | 承担有明确目标的较长任务，保留自己的工具过程；按 Harness 能力使用原生后台子 Agent 或独立工作 Session，不与话题一一绑定 |
| 任务 J1 / J2 | Core 中的持久记录，关联 C1、请求消息、任务版本、工作上下文 ID、状态和结果；不是模型会话，不随主 Session 换段丢失 |
| 话题 T1 / T2 | 目标、状态、未决事项和证据的记录；不是 Session，也不承担输入路由 |
| 上下文管家 CM | 预算触发的一次短模型调用，建议原生压缩或换段；由 Core 校验并执行，不接用户问题、不替换原生摘要算法 |
| 记忆整理 M | 空闲时按新增水位批量提出记忆变更；不常驻、不每轮运行 |
| Core | 持久化、检索、其管理资源的范围校验、任务状态与结果事件、消息回执、版本、原生 Session 生命周期；不取代继承的原生权限体系 |
| 个人会话 P0 | 所有者原有工作会话；与分身分开，不自动导入私人历史 |

普通消息进入当前主 Session，由它结合近期原文、焦点与未决项理解含义；不先调用独立模型将消息硬分成“新问题 / 追问”。“回到刚才那个”先从现有上下文和原始记录中找依据，仍有歧义再自然澄清对象。

空间内多人发消息仍进入同一个 C1，由 Core 保留作者和顺序、协调投递给当前主 Session；这不向每位成员直接开放原生 Session 控制。个人偏好归属实际表达者，不因为对话共享就自动成为全空间规则。与现有空间阅读规则保持一致；继承的原生工具仍按本机配置访问资源，不能把聊天可见范围说成完整工具隔离。

Core 持久保存原始记录、话题、记忆和来源范围；原生 Harness 仍负责模型调用、原生历史组织、工具循环和自身压缩。Core 不能假定能逐轮任意重写 Harness 的全部上下文。需要它知道的状态，通过受控增量、交接包或读取工具提供。

### 主 Agent 如何在长调查期间继续响应

S1 收到长调查要求后建立 J1，把目标、相关原话、约束、代码版本和证据入口交给 W1；派发成功后简短说明进度并结束这一轮。用户下一句话仍进入 S1，可以讨论另一话题、询问进度或调整 J1。短问题无需创建工作 Agent。

W1 完成后先保存结果与来源，再发出完成事件。Core 依据 C1 找到当时的主 Session（可能已是 S2），由主 Agent 核对任务版本、整合并答复；工作 Agent 不各自抢着向用户发答案。主上下文只保留任务索引、必要进度与结果摘要，完整工具过程留在 W1 的记录里，按需回读。

“只有一个主 Session”约束的是对话入口；它不要求长调查串行占用前台。主会话自身的一轮生成仍可能短暂忙碌，新输入按原生能力补充、中断或短暂排队，不承诺零延迟。调度上优先前台输入、限制后台并发；模型服务的共享并发或速率限制仍会影响响应。

需要落实的协调规则：

- **改要求**：递增任务版本，通知可接收补充的工作 Agent；旧版本结果可作资料，不能冒充已满足新要求。
- **取消**：区分已请求停止与实际停止；在确认前不说“已取消完成”，不因状态未知自动重跑任务。
- **换段**：J1 属于 C1，S2 继承任务 ID、版本、状态与结果水位；结果投递按事件 ID 去重，不直接绑定已经退出前台的 S1。
- **原生接入**：优先利用可观测、可恢复的后台子 Agent。若它不能跨主轮结束继续运行，或不能在换段后可靠回传结果，则从任务创建时就使用同一 Harness 的独立工作 Session，由 Core 管理。不能仅因存在 spawn 能力就声称已保证前台可响应，也不把运行中的原生子 Agent 假装迁移到 S2。
- **配置继承**：工作 Agent 按原生规则继承配置；原生角色自身的模型或工具限制仍有效，Team Cross 不额外裁剪，也不绕过原生限制。针对本机有效策略验证可用路径。

### 什么时候新建 Session

1. 首条消息创建 S1。
2. 接近预算时，CM 结合近期原话、未决事项和真实工具状态，建议原地压缩或在安全边界创建 S2。
3. 换段先短暂停止主会话新输入投递、核对主轮工具和回执，写入交接包及后台任务索引；S2 接手成功后才更新 C1 指向。可独立运行的 W1 不必等到完成，原生子 Agent 则必须有经过验证的存续与结果回传机制。
4. 关闭运行进程或普通断线先恢复保存的准确原生 ID，不因连接失败就创建新 Session 并重发。
5. 已加载资料撤权等范围变化可能要求重建同一 Harness 内的新段；不会因此迁移到另一个 Harness。
6. 明确的长调查按需创建工作上下文；它的生命周期由任务决定，不由“新问题 / 追问”决定。其上下文超限也需独立压缩或检查点接续，不能挤占主会话预算。

所有未完成要求、用户关键约束、近期原话和来源锚点都要进入交接。摘要是有损的，原始档案和可检索锚点用于补足细节；保底交接无法保证继续时明确暂停。单纯追加“忽略之前的内容”不能释放已占用的上下文。

### 上下文管家与原生压缩怎样配合

CM 保留在首版设计中。Core 观察上下文用量，在预判线附近且满足检查间隔时发起一次短调用，提供近期原话、未决项、后台任务状态、压缩次数和真实执行状态。CM 只返回 `compact` 或 `switch` 及理由；普通消息不经过它，不为每个问题创建一个管家会话，也不要求另选小模型。

| CM 的建议 | Core 的检查与动作 | 执行后的主会话 |
| --- | --- | --- |
| `compact`：当前工作适合继续衔接 | 等到原生允许的边界，调用经过验证的原生压缩接口；摘要如何生成仍由 Harness 决定 | 仍是 S1 |
| `switch`：适合交接到新段 | 核对工具、审批、投递与任务状态，生成交接包；S2 接手成功后更新 C1 指向 | S2 接任，S1 留作历史 |

原生自动压缩仍可自行触发。Core 发现压缩已经开始就等待结果，完成后重新读取用量并更新检查水位；若已回到预算内，则丢弃过时的 CM 建议，避免紧接着重复压缩或换段。管家是策略判断，Core 是状态协调，Harness 是原生执行；三者不各自并发修改同一段。

CM 请求失败或建议已经过时，有余量就延后检查；逼近预算时按真实状态使用原生压缩或保底交接。主轮仍有未决工具、审批或投递时，先核对处理，不能为了换段重放操作。预判线、冷却间隔与交接预算由 eval 调整，本记录不把 DS Bot 的数值直接固定为产品保证。

### 送达与手动重发

“已送达”只表示分身所在 Mac 的 Core 已持久接收消息，不等于模型已经回答或任务完成。发送失败保留该条内容并显示“重发”；不增加云端信箱、定时重试或联网后自动发送。

重发复用原消息 ID 和内容；接收端对重复 ID 返回已有接收状态，不重复创建模型输入或后台任务。回执丢失时重发仍核对同一 ID；若 Core 已接收而原生投递结果不明，继续核对原投递状态，不直接再执行。用户编辑内容后发送属于新消息。

### 记忆如何保持可信

- 对话状态、阶段结论、长期偏好分别存放，不能把所有摘要都当作永久事实。
- 明确的“记住 / 修改 / 忘掉”在当前轮通过受控工具落实，持久化成功后才确认；新增或纠正下一轮可见。
- 隐含经验由 M 批量整理；推测保持候选，用户纠正优先。写入校验版本并按来源去重，成功后才推进处理水位。
- 记忆携带表达者、适用对象、可见范围、来源、版本与失效状态。同事自己的偏好不自动修改所有者偏好，私人讨论不自动成为团队决定。
- 段开始的少量稳定记忆与索引有助于缓存；段内通过增量与 recall 取得最新状态，不反复发送整个记忆库。
- 停用记忆、删除原始聊天、撤销资料访问分别定义语义；联动派生摘要、检索索引和已加载上下文。不能宣称能撤回已经发出的答复。
- 上述范围检查约束 Core 管理的记忆与检索；全量继承的原生自动记忆、hooks 和外部 MCP 仍遵循本机配置，不能声称 Core 已隔离它们的所有数据访问。配置继承不等于把个人会话 P0 的完整 transcript 当作分身启动上下文。

### 选择 Harness 的实际边界

创建时选择本机可执行入口与现有配置，后续持久保存 Harness、准确原生 Session ID 及必要的恢复信息。主 Session、工作 Agent、CM 和 M 都经选定 Harness 执行，遵循用户已有的模型与子 Agent 配置；Team Cross 不擅自改换路由、指定另一服务或要求新的 Token Plan。产品不固定模型或推理强度。

| 层次 | 谁负责 |
| --- | --- |
| Harness | Codex / Claude Code 提供会话、工具循环、子 Agent、压缩与恢复 |
| 模型路由 | 本机有效配置决定端点、认证、模型与网关；协议和工具能力需要兼容 |
| Token Plan / 计费 | 由实际使用的账户与服务决定，不作为分身的产品分支；新增模型请求仍计入原有用量 |
| 分身管理 | Core 保存聊天、任务、记忆与交接状态，调用既有运行环境 |

Codex 官方提供自定义模型 Provider；Claude Code 官方提供网关接入，但明确不为通过网关运行非 Claude 模型提供支持。“第三方提供 Claude 服务”与“通过兼容接口运行其他模型”须分别表述。产品沿用用户本机可用的配置，不能因此保证任意第三方模型都具备等价的工具、上下文和子 Agent 行为。

Codex 以 app-server 为候选程序接口；Claude Code 选择能保留现有配置、认证和后台能力的本机程序接口。不能为方便接 SDK 或使用 bare 模式，静默改变用户的既有环境。当前仓库的 [Claude 原生 TUI 契约](../../sources/decisions/claude-native-tui.md)针对后台原生 job，其控制 API 有自己的边界；需要验证适合分身的输入、事件、恢复与后台执行路径，但这是接口适配问题，不是把分身绑定到某家套餐的理由。

全量继承指按原生配置优先级和已有策略加载，包括 hooks、插件、skills、MCP、权限、自动记忆及子 Agent 设置；不另设空配置目录或工具白名单。Core 只记录运行所需引用与非敏感配置指纹，不将凭据写进任务记录、提示词或演示。启动、换段和恢复以原生实际加载结果为准，配置改变需要重新检查，不能宣称一个永久冻结的副本仍是当前配置。

创建时检查输入、历史读取、准确恢复、有效配置与用量可观测能力；用量不足时验证保守预算能否可靠换段。显式压缩、中断和后台结果回传按实际能力实现。本机 Harness 不代表模型推理一定发生在本机；“调查为默认工作方式”也不等于强制只读沙箱。

## 需要理解的取舍

以下为推荐选择，尚未全部转为产品决策或实现要求。

| 取舍 | 对使用者的影响 | 推荐起点 / 重新评估条件 |
| --- | --- | --- |
| 自然连续与话题隔离 | 一个 Session 中可能误用另一个话题的条件 | 明确全局偏好与任务约束，保留关键原文；用 A → B → A 回放检验串题 |
| 前台响应与后台协调 | 主 Agent 可以继续聊，但结果可能晚到、任务可能被改要求或取消 | 首版即采用主 Agent 加后台工作 Agent；任务版本、结果去重和前台优先调度一起实现 |
| 无感换段与成本 | 摘要可能遗失细节，回读、CM、M 和交接都有调用与延迟成本 | CM 预算触发、M 空闲批量且设上限；用遗失率、额外调用和耗时判断收益 |
| 主动记忆与错误累积 | 临时要求、同事意见或旧代码事实可能被误记为永久真相 | 明确记忆优先、推断候选化、来源可追溯、纠正及时生效 |
| Harness 选择与能力一致 | 两种运行时的压缩、恢复、权限和事件能力不同，升级也可能改变行为 | 先跑通 Codex，再适配 Claude；统一聊天与记忆语义，逐组合验收 |
| 全量继承与复现性 | 同一套分身会受本机 hooks、插件、MCP、模型路由和权限变化影响 | 首版全量继承已确认；记录有效配置指纹，在实际配置上 eval，不再另外裁剪工具或承诺硬隔离 |
| 本机现场与持续在线 | Mac 休眠、断网时无法调查；远端模型仍会接收选入请求的资料 | 接收端持久化后显示已送达，失败时提供手动重发；同 ID 去重，不增加云端信箱或自动重发 |
| 最新文件与版本一致 | 调查期间文件改变可能让同一结论混用多个现场 | 记录提交、dirty 状态与关键文件指纹；变化时重读，精确回放另需快照 |
| 完整追溯与保留成本 | 历史和工具输出增长，停用记忆与删除原文的预期不同 | 明确保留策略与删除动作；关键证据和普通输出分开处理 |
| 快速调参与可靠 eval | 小样本易过拟合，Harness / 模型 / 工具配置增加验证组合 | 公共场景共享，原生接入单独验证；留出样本、重复运行、长期回放 |

## Eval 如何落地

先建立可重放的脱敏或合成对话，建议首批 30 条覆盖六类：话题来回切换、指代与多项要求、压缩与连续换段、记忆纠正与失效、后台调度和故障、Core 管理来源的范围与资料伪指令。冻结 10 条作留出检查，其余用于调参；这只是筛选方案的起点，不能当作充分验收。

比较三组基线：原生长会话及压缩、预算触发换段、预算加 CM / 话题状态 / 记忆增量。同组固定模型与有效配置，记录未决项保留、关键原话与证据正确、澄清次数、总 token、额外调用、首响应与总耗时。真实投递、工具状态和来源范围用断言；回答质量用有依据的评分与人工抽查。串权、重复投递和虚报完成单独判失败。

“爬山”用于离线迭代：每次只改一个因素，重复比较，通过硬性检查且质量不退步、目标成本改善才保留，再跑留出样本。它不保证全局最优，也不是线上自动改规则。DS Bot 的公开 eval 是手写 compact / switch / either 场景并重复真实模型调用，本身没有自动搜索参数的循环。

原生接入、模型回答和长期积累分别检验；一个 Harness 通过不能推广到另一个。真实模型验证继续遵守[项目验证契约](../../sources/validation/test-gates.md)的模型与测试现场限制。设计阶段未执行上述 eval；后续 Codex 实现及已执行的接续回放见[实现记录](implementation.md)，不将有限验收等同于长期质量优化。

后台场景必须覆盖：W1 长时间运行时主 Agent 回答另一问题、用户改要求后旧结果晚到、取消请求与真正停止、S1 → S2 期间 W1 完成、重复完成事件、工作 Agent 失败和原生权限等待。响应指标区分接收回执、主 Agent 的实质回应、后台结果完成；快速显示“收到”不算验证了可响应。记录后台并发与模型服务限流，比较主会话是否被后台工作挤占。

本轮确认后的回归还需覆盖：空间内多人接续同一个 C1 且保留作者和偏好归属；原生自动压缩先完成时不执行过时的 CM 建议；回执丢失后手动重发同一消息只投递一次。首轮以 Codex 完成上述验证，Claude 后续单独验收。

有效配置是实验条件的一部分：版本、模型路由、原生角色、hooks、插件、skills、MCP 与权限指纹随结果记录且不含凭据。Core 记忆范围测试不替代全量继承工具的访问边界验证；不把提示词里的“只读”算作技术隔离通过。
