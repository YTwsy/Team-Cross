模型 / Prompt

理解新消息、按来源回复、保留尚未完成的要求。需要时补问；长工作才派 W。

Core / 原生事件

保存原文、去重、确定性路由和投递。普通消息不维护条件、依赖满足与自动结案。

能力边界

可追加输入不等于立即回答。工具、审批、压缩和切段可能延迟处理；原生未接收的输入留在可靠收件箱。

Claude Channels 的官方行为是忙时排队、下一轮一起处理。这里借鉴其消息流模式；Codex 采用自己的 start / steer 协议，并不使用 Claude 的通知协议。

连续提问：看 S 与 W 同时在做什么

示意先后顺序，不表示耗时或响应承诺
同一段协作① 接收② 开始处理③ 新输入④ 中间结果⑤ 继续⑥ 收尾

一条有序输入流

新问题、普通答复、需要模型判断的结果都按到达顺序投递。取消按业务类型轮换的额外调度队列。

只保留必要归属

每条输入保留作者、消息 ID 和回复来源；明确属于 W 的答复路由到 W，普通消息进入当前 S。

合批控制体积

不逐条开启完整 turn，不等消息“都到齐”才投递。长正文留来源入口，原文保留；自身已发布消息的回声去重。

注入的是与该分身有关的新信息，不复制全部空间历史或 W 工具日志。原生明确拒绝过期 turn 时重新定位；发送结果未知时先核对，不盲目重发。取消仍走明确控制入口。

真正的后台工作

主会话派活；W 在需要时报告。

shadow_task(start / report)
日常主路径两种操作；管理操作仍按需保留。
操作模型主要提供Core 负责
start工作要求、标题；必要时列明完成条件绑定原请求与回传路线，保存 Job，调度 W；立即返回派发回执
report: continue已确认的进展 / 可公开的阶段答案；可选检查点持久化进展与待发送正文，送回绑定来源；W 可继续工具调用
report: wait缺少什么、已登记的等待对象、收到后的下一步保存等待关系；原生轮次结束后释放工作槽，真实答复到达后接续
report: complete / fail结果与依据；已有完成条件的核对核对归属 / 版本 / 阻塞依赖，同次保存业务结果与 Outbox
status / update / cancel / resume仅在查看、改目标、取消、恢复时调用沿用单套任务记录；版本和真实执行状态由宿主核对
W 内 task ID 与版本从当前 Run 绑定，模型不搬运 baseVersion / baseRevision。按操作收窄参数；不再要求 understand、replan、contextReviews 或直接回复后的 Observation JSON。
本次真正删除的复杂度：普通问答没有任务完成状态，只保留已发送、收到新回复等消息事实；理解、追问和继续回答交给模型。严格的等待对象、业务完成判断只属于显式 Work。不是把这些规则藏进另一套“轻量任务”。

业务事实

完成后不因网络送达失败而退回未完成。原生 final 只代表回合结束，不代替业务完成提交。

发送事实

阶段回报可直接送达；需要综合决策才叫 S。公开工具已经发过的正文按回执关联，避免再发一份。

摘要整理

异步更新相关认识，不挡回复、等待或完成；失败只留下待整理记录。

“直接”表示无需再跑 S 模型改写。跨 Core 仍按原 Outbox 送达；个人发起会话仍经既有 MCP / Hook 通道，不新增自动启动接收模型的机制。发送结果未知先核对，不盲目重发。

本次推进边界

保留底座

  • 当前 S、独立 W、现有换段与记忆维护
  • 一套 Job / 问题 / 动作记录
  • 准确来源、版本校验、去重与 Outbox
  • 原生权限、审批与明确取消 / 恢复
  • 本人接回具体问题的处理归属

本次做减法

  • 移除认识更新对回复 / 完成的硬阻塞
  • 普通补问不创建业务等待任务
  • 日常后台工作围绕 start / report
  • 统一消息流；空闲 start、运行中 steer
  • 普通关注只收件，按需 / 按备注处理

本次不跟进

  • 侧边问答 / side / btw
  • 普通关注的独立观察流水线
  • 多级派活树与自动递归委派
  • 复杂 watch 目标和多认识联动
  • 15 秒强停、自动搬迁在途原生回合

推进顺序与验收重点

以下为待执行验证，不代表已经通过
  1. 先验证输入：同一 S 运行中接受多条新增消息；保留每条作者与准确回复目标，不把一轮结束当成每条问题均已答复。
  2. 再退出普通任务化：普通回复 / 补问直接走消息，移除条件、等待与结案前置；真实来源路由继续有效。
  3. 收敛 Work：start / report、阶段回报直达；完成独立于送达与摘要整理。
  4. 验证边界：连续输入、审批等待、turn 切换竞争、重启与回执丢失下不串作者、不丢消息、不重复执行。
