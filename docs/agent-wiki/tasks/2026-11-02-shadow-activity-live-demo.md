## 已定位的关注问题

两次普通观察都正常结束并生成结构化内容；失败发生在 Core 保存认识时。实际错误是 `观察结果无效，未推进处理位置: 证据未在本批或此前有效认识中提供`。

对照原生输入中的 sources / references 与输出发现：

- 讨论包允许的回复引用只有 spaceId、annotationId、replyId；模型又从回复正文对象复制了业务 requestId。它不是本次允许引用中的字段。
- 材料初始化允许引用固定 materialId / version；模型根据已读正文补上 turnId / itemIds，组成了没有列入允许集合的更细引用。
- 校验按整个来源结构匹配允许集合，因此两者均被拒绝。模型确实收到并读懂了正文，不等于认识已经可靠保存；`attentionCommitted` 只表示该原生结果已交给处理逻辑，不表示保存成功。
- v2 后续信号的存在只证明接收，不能从它推导旧错误已恢复。本轮保留了失败与队列，没有绕过证据校验、修改状态或通过重复模型轮次掩盖问题。

代码位置为 [观察输出结构](../../../internal/shadow/attention_engine.go)及[来源验证与认识保存](../../../internal/shadow/attention_batches.go)。后续修复应减少模型自行拼写完整来源字段的责任，例如由 Core 提供可选的准确来源 ID 并还原引用；仍需保留对象、版本、成员与空间校验，不能简单接受模型新增的任意字段。该方向尚未实施。
